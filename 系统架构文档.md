### 2.3 AI 服务调用链

```
┌──────────────────────────────────────────────────────────────────┐
│                        AI 服务调用链                              │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│ ① AI智能导诊 (AiAppointmentService)                              │
│    症状输入 → 查询科室/医生/排班 → 构建Prompt → Qwen LLM         │
│    → JSON解析 → AppointmentRecommendation                        │
│    多轮: 用户消息+历史 → LLM判断 → 未完成继续/完成自动推荐        │
│                                                                  │
│ ② AI药品推荐 (AiMedicineService) — RAG流程                      │
│    症状输入 → EmbeddingModel.embed() → 向量检索Top-10            │
│    → 构建上下文(含相似度) → Qwen LLM精排 → 3种药品推荐           │
│    索引构建: DB药品 → TextSegment → 批量向量化 → InMemoryStore   │
│    → 序列化磁盘缓存(medicine-embedding-store.json)               │
│                                                                  │
│ ③ AI费用解释 (AiBillingService)                                  │
│    费用列表+用户问题 → 构建Prompt → Qwen LLM                     │
│    → BillingExplanation(总额/构成/合理性/节省建议)                │
│    多轮: 用户消息+历史+费用数据 → LLM连续解释                     │
│                                                                  │
│ ④ AI报告生成 (AiReportService) — CoT思维链                      │
│    病历+检查数据+历史上下文 → 5步思维链 → ReportResult            │
│    SSE流式: 6个步骤实时推送 → 思维链 → 完整报告                   │
│    5步: ①分析主诉现病史→②结合检查→③参考历史→④综合诊断→⑤治疗方案  │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 统一响应格式

```typescript
interface Result<T> {
  success: boolean;    // 操作是否成功
  errorMsg: string;    // 错误信息(失败时)
  data: T;            // 业务数据
  total: number;      // 分页总数
}
```

### 3.3 SSE 流式事件格式 (报告生成)

| 事件类型 | 数据结构 | 说明 |
|---------|---------|------|
| `step` | `{step, title, message, progress}` | 6步生成进度 |
| `thoughtchain` | `{aiThoughtChain}` | AI思维链内容 |
| `complete` | `MedicalReport` | 完整报告对象 |
| `error` | `{message}` | 错误信息 |
| `finish` | - | 生成结束信号 |

### 3.4 前后端跨层接口协议

```
前端 Axios 实例                    后端 Spring Boot
────────────────                    ───────────────
baseURL: /HIS         ←匹配→      context-path: /HIS
withCredentials: true  ←匹配→      HttpSession 会话管理
Content-Type: JSON     ←匹配→      @RequestBody DTO
响应拦截 401 → /login  ←匹配→      LoginInterceptor 返回 401
```

### 4.4 交互模式总结

| 交互模式 | 使用场景 | 实现方式 |
|---------|---------|---------|
| **表单提交** | 登录/注册/修改信息/创建预约 | Element Plus表单校验 + API POST/PUT |
| **表格浏览** | 预约列表/费用列表/病历列表/药品列表/报告列表 | el-table + el-pagination 分页 |
| **AI多轮对话** | 智能导诊/药品推荐/费用解释 | 聊天气泡UI + 流式输入动画 + SSE |
| **SSE流式展示** | AI报告生成 | fetch + ReadableStream + 进度条 + 步骤指示器 |
| **卡片选择** | 新建预约选医生/AI生成选病历 | 可点击卡片 + 选中高亮 |
| **图表可视化** | 费用构成分析 | SVG环形饼图(BillingPieChart) |
| **文件操作** | 头像上传/报告PDF导出 | multipart/form-data + Blob下载 |
| **弹窗详情** | 病历详情/药品详情/报告详情/排班选择 | el-dialog (宽度400px~1400px) |

## 五、数据模型关系

### 5.1 实体关系图 (ER)

```
patient (account PK) ──1:N──> medical_record (patient_id FK)
                           ──1:N──> appointment (patient_id FK)
                           ──1:N──> billing (patient_id FK)
                           ──1:N──> prescription (patient_id FK)

department (id PK) ──1:N──> doctor (department_id FK)

doctor (id PK) ──1:N──> medical_record (doctor_id FK)
                     ──1:N──> appointment (doctor_id FK)
                     ──1:N──> prescription (doctor_id FK)
                     ──1:N──> doctor_schedule (doctor_id FK)

medical_record (id PK) ──1:1──> medical_report (medical_record_id FK)
                        ──1:1──> prescription (medical_record_id FK)
                        ──1:N──> billing (medical_record_id FK)

appointment (id PK) ──1:N──> billing (appointment_id FK)

prescription (id PK) ──1:N──> prescription_item (prescription_id FK)
medicine (id PK) ──1:N──> prescription_item (medicine_id FK)
```

### 5.2 核心实体字段

| 实体 | 核心字段 | 说明 |
|------|---------|------|
| Patient | account(UUID), username, name, password(BCrypt), gender, age, idCard, phone, address, avatar | 患者主键为UUID自动生成 |
| Department | id, name, description, location, status | 科室名称唯一 |
| Doctor | id, name, gender, age, title, departmentId, specialty, phone, status | 含非DB字段departmentName |
| DoctorSchedule | id, doctorId, scheduleDate, timeSlot, maxPatients(默认20), bookedCount, status | 排班表，支持原子递增/递减 |
| Appointment | id, patientId, doctorId, departmentId, appointmentType, appointmentDate, timeSlot, status(0预约/1完成/2取消), aiRecommended | 支持医生预约和检查预约 |
| MedicalRecord | id, patientId, doctorId, departmentId, chiefComplaint, presentIllness, diagnosis, treatmentPlan, visitDate, status | 电子病历 |
| MedicalReport | id, patientId, medicalRecordId, doctorId, reportType, title, examinationData, aiSummary, aiDiagnosis, aiTreatment, aiRecommendation, aiThoughtChain, pdfPath, status(0草稿/1确认/2作废) | 含4个AI生成字段 |
| Medicine | id, name, genericName, category, specification, manufacturer, ingredients, efficacy, sideEffects, contraindications, dosage, price, stock, status | 药品完整信息 |
| Billing | id, patientId, appointmentId, medicalRecordId, itemType(挂号/检查/药品/其他), itemName, amount, description, status(0未付/1已付/2已退款) | 费用记录 |
| Prescription | id, medicalRecordId, patientId, doctorId, prescriptionDate, status(0待取药/1已取药/2已取消) | 处方 |
| PrescriptionItem | id, prescriptionId, medicineId, dosage, quantity, days, remark | 处方明细 |

## 六、技术架构总结

### 6.1 技术栈

| 层次 | 技术选型 |
|------|---------|
| 前端框架 | Vue 3 (Composition API + `<script setup>`) |
| 前端UI | Element Plus + TypeScript |
| 前端状态 | Pinia |
| 前端路由 | Vue Router 4 (HTML5 History) |
| 前端构建 | Vite |
| 后端框架 | Spring Boot |
| ORM | MyBatis-Plus |
| 数据库 | MySQL |
| 缓存 | Redis (验证码/分布式锁) |
| AI模型 | 通义千问 Qwen (qwen-plus) via DashScope |
| AI嵌入 | text-embedding-v2 (RAG药品推荐) |
| AI框架 | LangChain4j |
| PDF生成 | iTextPDF |
| 会话管理 | HttpSession |

### 6.2 关键技术亮点

1. **AI深度集成**: 4大AI服务覆盖预约导诊、药品推荐(RAG)、费用解释、报告生成(CoT)全业务场景
2. **RAG药品推荐**: 真正的向量检索+LLM精排流程，InMemoryEmbeddingStore+磁盘缓存优化
3. **并发控制**: 预约/取消使用 Redis分布式锁 + MySQL原子SQL双重保障防超卖
4. **SSE流式报告**: 实时推送6步思维链进度，用户体验友好
5. **权限体系**: 基于Session的4级角色(patient/doctor/pharmacist/admin)权限控制，贯穿Controller和Service层
6. **身份证脱敏**: 默认前3位+\*\*\*+后4位，需密码验证才可查看完整号码
7. **统一响应格式**: Result\<T\> 封装 success/errorMsg/data/total
