# 医院信息系统 - 患者账户模块 API 开发文档

## 1. 接口说明

全局 context_path: `/`

| 功能 | 方法 | 路径 | 是否需要登录 |
|------|------|------|-------------|
| 用户注册 | POST | /patient/register | ❌ 否 |
| 用户登录 | POST | /patient/login | ❌ 否 |
| 用户登出 | POST | /patient/loginout | ✅ 是 |
| 查看个人信息 | GET | /patient/me | ✅ 是 |
| 修改个人信息 | PUT | /patient/me/update | ✅ 是 |

---

## 2. 流程说明

### 2.1 用户注册流程

1. 查询手机号、身份证号是否符合规矩，不符合则返回错误消息"手机号或身份证格式不正确"
2. 查询手机号或身份证是否已经被注册，若已被注册，返回错误消息"该手机号或身份证已被注册"
3. 判断两次密码是否一致，若不一致返回"两次密码不一致"
4. 满足注册要求
   4.1 UUID 随机分配唯一 account
   4.2 保存用户信息到数据库中（密码加密存储）
   4.3 返回保存成功/失败消息

**请求参数：**
```json
{
  "name": "姓名",
  "username": "用户名",
  "password": "密码",
  "confirmPassword": "确认密码",
  "gender": "性别",
  "age": 年龄,
  "phone": "手机号",
  "address": "地址",
  "idCard": "身份证号"
}
```

---

### 2.2 用户登录流程

1. 获取手机号和密码
2. 判断手机号格式是否正确，不正确返回"手机号格式不正确"
3. 判断手机号是否存在，不存在返回"手机号不存在"
4. 判断密码是否正确，不正确返回"密码不正确"
5. 登录成功
   5.1 构建 PatientInfoVo 对象，包含患者基本信息
   5.2 将 patientInfoVo 对象存入 session
   5.3 将 phone 存入 session
   5.4 返回用户信息

**请求参数：**
```json
{
  "phone": "手机号",
  "password": "密码"
}
```

**Session 存储：**
- `session.setAttribute("patient", patientInfoVo)`
- `session.setAttribute("phone", phone)`

---

### 2.3 用户登出流程

1. 移除 session 中的 user 属性
2. 使 session 失效（invalidate）
3. 返回"登出成功"

---

### 2.4 查看个人信息流程

1. 从 session 中获取用户信息
2. 返回用户信息

**注意：** 该接口已通过登录拦截器验证，无需再判断 session 是否存在

---

### 2.5 修改个人信息流程

1. 从 session 中获取当前用户的手机号
2. 获取当前用户的密码
3. 根据手机号查询用户信息
4. 验证密码是否正确，不正确返回"密码不正确"
5. 获取要修改的信息：地址、电话、用户名（只更新非空字段）
6. 如果新电话非空
   6.1 验证手机号格式，不正确返回"手机号格式不正确"
   6.2 查询手机号是否已被注册，已注册返回"该手机号已被注册"
7. 进行数据库更新（使用条件更新，只更新非空字段）
8. 返回"修改成功"

**请求参数：**
```json
{
  "username": "新用户名（可选）",
  "phone": "新手机号（可选）",
  "address": "新地址（可选）",
  "password": "当前密码（必填，用于身份验证）"
}
```

**注意：**
- password 为必填项，用于验证身份
- 其他字段为可选，不填则不修改
- 不允许修改身份证号

---

## 3. 拦截器说明

### 登录拦截器（LoginInterceptor）

**拦截路径：** `/**`（所有路径）

**排除路径：**
- `/patient/login/**` - 登录及忘记密码接口
- `/patient/register` - 注册接口
- `/error` - 错误页面
- `/static/**` - 静态资源

**拦截逻辑：**
1. 获取 session
2. 从 session 中获取 phone 属性
3. 判断 phone 是否为 null
4. 若为 null，返回 401 状态码和错误消息"请先登录"，拦截请求
5. 若不为 null，放行请求

**注意：** 所有需要登录的接口（查看信息、修改信息、登出等）都不需要在业务层再次判断 session 是否存在，因为拦截器已统一处理。
