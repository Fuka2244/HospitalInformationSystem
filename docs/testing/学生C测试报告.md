# 医院信息系统学生 C 测试报告

## 一、项目名称、简介与功能点

### 1. 项目名称

医院信息系统（Hospital Information System，简称 HIS）

### 2. 项目简介

医院信息系统是一个面向患者、医生、药师和管理员的综合医疗服务平台。系统采用前后端分离架构，后端基于 Spring Boot，前端基于 Vue 3，数据库使用 MySQL，并结合 Redis、JWT、AI 服务等技术实现医疗业务管理。

系统主要功能包括患者登录注册、预约挂号、AI 导诊、病历查询、药品查询、AI 药品推荐、费用查询、AI 费用解释、医疗报告生成、医生工作台、药师工作台、管理员控制台等。系统能够模拟医院日常业务流程，为患者提供在线查询和辅助医疗服务，同时为医生、药师和管理员提供相应的业务处理入口。

## 三、测试方法选择与分析

本次测试采用黑盒测试方法，不关注系统内部代码实现，而是从用户输入、页面操作和系统输出角度验证功能是否符合预期。主要使用以下测试方法：

### 1. 等价类划分法

等价类划分法用于将输入数据划分为有效等价类和无效等价类。例如药品搜索关键词可以分为有效药品名称、不存在药品名称、特殊字符等；AI 药品输入可以分为常见症状、空输入、无意义输入等。

适用模块：

- F09 药品查询
- F10 AI 药品推荐
- F11 费用查询
- F12 医疗报告

### 2. 边界值分析法

边界值分析法主要用于测试输入边界，例如空输入、无数据、未选择病历、非法条件等。由于系统中很多功能都有输入限制，因此边界值测试有助于发现参数校验和页面提示问题。

适用模块：

- AI 药品输入为空
- 费用查询未登录
- 医疗报告未选择病历
- 搜索关键词为空或特殊字符

### 3. 判定表法

判定表法适用于多个条件组合形成不同结果的功能。例如登录状态不同会导致费用页和报告页访问结果不同；是否选择病历会影响生成报告按钮是否可用；是否有报告数据会影响是否显示详情和 PDF 导出按钮。

适用模块：

- F11 费用查询权限判断
- F12 医疗报告权限判断
- F12 报告生成状态判断

### 4. 错误推测法

错误推测法根据经验设计容易出错的场景，例如特殊字符搜索、无意义 AI 输入、无数据列表、未登录访问等。这些场景可能触发页面空白、请求异常或错误提示不明确的问题。

适用模块：

- F09 特殊字符搜索
- F10 无意义 AI 输入
- F11 未登录访问费用页
- F12 未登录访问报告页

## 五、测试用例讨论与修改

在完成初始测试用例设计后，本人向小组成员说明了测试设计思路。最初设计的用例主要集中在正常流程，例如药品查询、AI 输入、费用列表和报告列表。经过讨论后，小组成员提出以下建议：

1. 查询类功能不能只测试正常数据，还应加入不存在关键词和特殊字符。
2. AI 类功能结果具有不确定性，自动化脚本不应强依赖 AI 最终回复内容，应重点验证输入校验和提交行为。
3. 费用查询和医疗报告属于登录后功能，需要测试未登录访问时是否跳转登录页。
4. 医疗报告生成需要测试未选择病历时按钮是否禁用，防止用户误操作。
5. 如果列表无数据，脚本不应直接失败，而应接受“空数据提示”作为合理结果。

根据讨论意见，最终测试用例加入了空输入、特殊字符、未登录访问、无数据场景和按钮禁用状态等测试，使测试用例更容易发现实际缺陷。

### 3. 核心脚本示例

以下为药品查询模块中的一个测试脚本示例：

```java
@Test
@DisplayName("F09-02 输入有效关键词查询，应返回药品列表或无数据提示")
void shouldSearchMedicineByKeyword() {
    open("/medicine");

    type(By.cssSelector(".filters input[placeholder*='搜索']"), "阿莫西林");
    click(By.cssSelector(".filters .el-button--primary"));

    visible(By.cssSelector(".el-table"));
    assertTrue(hasRows() || !all(By.cssSelector(".el-table__empty-text")).isEmpty(),
            "关键词查询后应显示结果或空数据提示");
}
```

该脚本首先打开药品查询页面，然后输入关键词并点击搜索按钮，最后判断系统是否显示查询结果或空数据提示。

## 十一、脚本开发中遇到的问题

### 1. AI 返回结果不稳定

AI 药品推荐和 AI 费用解释的返回内容依赖模型服务，同样的输入可能产生不同回复。如果脚本强行判断 AI 文本内容，容易导致测试不稳定。因此脚本只验证输入提交、用户消息显示和页面不崩溃，不强制判断 AI 最终推荐结果。

### 2. 登录态影响测试结果

费用查询和医疗报告属于登录后才能访问的页面。如果测试账号不存在或密码错误，会导致脚本停留在登录页。为解决该问题，公共测试基类中封装了患者登录方法，并支持通过 Maven 参数传入账号和密码。

### 3. 页面数据可能为空

药品、费用、报告列表在不同数据库环境下数据量可能不同。为了增强脚本适应性，测试断言允许“有数据列表”和“空数据提示”两种合理结果。

### 4. Selenium 等待问题

页面加载和接口请求存在异步行为。如果直接查找元素，可能出现元素尚未加载完成导致测试失败。因此脚本中使用 WebDriverWait 显式等待页面元素出现，提高测试稳定性。

### 5. 浏览器驱动问题

Selenium 运行时可能出现浏览器驱动下载或版本不匹配问题。解决方式是使用较新版本的 Chrome 或 Edge，并保证网络可用。如果 Chrome 无法运行，可切换 Edge 执行。

## 十二、体会与总结

通过本次测试实验，我对黑盒测试方法和自动化测试流程有了更深入的理解。等价类划分法适合用于搜索、查询和输入验证；边界值分析法能够发现空输入、未选择数据、特殊字符等问题；判定表法适合处理登录状态、按钮状态和权限访问等条件组合。

在将测试用例转换为 Selenium 脚本时，我认识到自动化测试不只是简单模拟点击，还需要考虑页面加载、异步请求、登录状态、数据是否存在以及 AI 返回结果不稳定等因素。因此，在设计脚本时需要让断言既能验证关键功能，又不能过度依赖不稳定数据。

本次测试共执行 20 个自动化测试用例，覆盖了药品查询、AI 药品推荐、费用查询和医疗报告四个功能模块。最终测试全部通过，说明这些功能在当前测试环境下基本满足预期要求。后续如果继续完善测试，可以增加接口层测试、更多异常场景测试以及跨浏览器兼容性测试，从而进一步提高系统质量。
