# 🏥 医院信息系统（HIS）软件测试实验报告

---

## 一、项目概述

### 1.1 项目名称
**医院信息系统（Hospital Information System, HIS）**

### 1.2 项目简介
本项目是一个基于 **Spring Boot 3.2.5 + Vue.js 3** 的现代化医院信息管理系统，采用前后端分离架构。系统集成了通义千问 AI 大模型，实现智能导诊、药品推荐、费用解释、医疗报告生成等 AI 辅助功能。系统支持患者、医生、药师、管理员四种角色，覆盖预约挂号、电子病历、处方审核、药品库存管理、费用管理、医疗报告等核心医院业务流程。

### 1.3 技术栈
| 层级 | 技术 |
|------|------|
| 后端框架 | Spring Boot 3.2.5（Java 21） |
| ORM | MyBatis-Plus 3.5.5 |
| 数据库 | MySQL 8.0 |
| 缓存 | Redis |
| 消息队列 | Kafka |
| AI 服务 | LangChain4j 0.36.2 + 通义千问 (Qwen) |
| 安全认证 | JWT Token + BCrypt 密码加密 |
| 前端框架 | Vue.js 3 + Element Plus + TypeScript |
| 构建工具 | Vite |

### 4.1 FP-07 病历与就诊记录查看

**等价类划分法**：
- 就诊记录的筛选条件（科室ID、医生ID、日期范围）各可分为有效等价类和无效等价类
- 分页参数（page、size）有有效和无效等价类

**边界值分析法**：
- 分页参数 page 的边界：1（最小）、0（无效）、-1（无效）
- 分页参数 size 的边界：1（最小）、10（默认）、100（较大值）、0（无效）

### 7.2 测试脚本基类

```java
// BaseSeleniumTest.java
package com.hospitalinfo.hospitalinformationsystem.selenium;

import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.chrome.ChromeOptions;
import org.openqa.selenium.edge.EdgeDriver;
import org.openqa.selenium.edge.EdgeOptions;
import org.openqa.selenium.support.ui.WebDriverWait;

import java.time.Duration;

public abstract class BaseSeleniumTest {

    protected WebDriver driver;
    protected WebDriverWait wait;
    protected static final String BASE_URL = "http://localhost:5173";
    protected static final String API_URL = "http://localhost:8080/HIS";

    @BeforeEach
    public void setUp() {
        // Chrome 配置
        ChromeOptions chromeOptions = new ChromeOptions();
        chromeOptions.addArguments("--remote-allow-origins=*");
        chromeOptions.addArguments("--disable-blink-features=AutomationControlled");
        // chromeOptions.addArguments("--headless"); // 无头模式，CI环境使用

        driver = new ChromeDriver(chromeOptions);
        driver.manage().window().maximize();
        driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));
        driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(30));
        wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }

    @AfterEach
    public void tearDown() {
        if (driver != null) {
            driver.quit();
        }
    }

    /**
     * 切换到 Edge 浏览器
     */
    protected void useEdge() {
        if (driver != null) driver.quit();
        EdgeOptions edgeOptions = new EdgeOptions();
        edgeOptions.addArguments("--remote-allow-origins=*");
        driver = new EdgeDriver(edgeOptions);
        driver.manage().window().maximize();
        wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }
}
```

## 八、脚本开发中遇到的问题与解决方案

| 序号 | 问题描述 | 解决方案 |
|------|---------|---------|
| 1 | **Selenium 找不到元素**：页面使用 Vue.js 动态渲染，元素可能未加载完成 | 使用 `WebDriverWait` + `ExpectedConditions` 等待元素出现后再操作 |
| 2 | **Element Plus 组件选择困难**：el-select 下拉选项在 dropdown 中，不是子元素 | 先点击 select 触发下拉，再在全局范围查找 `.el-select-dropdown__item` |
| 3 | **AI 对话功能需要 API Key**：通义千问 API 需要有效的 Key | 测试时判断元素是否存在，不存在则跳过而非报错 |
| 4 | **Chrome 驱动版本匹配**：Selenium 4 内置驱动管理，但仍需确保 Chrome 版本兼容 | 使用 `WebDriverManager` 或确保 Chrome 浏览器版本与 Selenium 版本匹配 |
| 5 | **日期选择器交互**：Element Plus 的 el-date-picker 自定义输入需特殊处理 | 直接通过 `sendKeys` 写入日期字符串，而非点击日历选择 |
| 6 | **Vue 响应式更新导致 stale element**：操作后 DOM 重建 | 每次操作前重新查找元素，避免缓存 WebElement 引用 |

## 十一、体会与感想

### 11.1 测试方法与思路

1. **等价类划分法**在本项目中发挥了重要作用，特别是对输入参数的覆盖。例如药品查询的关键词、费用查询的筛选条件等，通过等价类划分有效减少了测试用例数量，同时保证了覆盖率。

2. **边界值分析法**在分页参数、日期范围等场景中发现了潜在问题（如 page=0 的处理），验证了"边界往往是 bug 集中区域"的经验。

3. **判定表法**适用于多条件组合筛选场景（如费用查询），能系统地覆盖各种条件组合，避免遗漏。

### 11.2 Selenium 自动化测试体会

1. **等待机制是关键**：Vue.js 单页应用的动态渲染给 Selenium 定位元素带来挑战，`WebDriverWait` 比 `Thread.sleep()` 更可靠。

2. **Element Plus 组件库的定位**：Element Plus 的下拉菜单、日期选择器等组件使用 Portal 渲染（挂载到 body），需要特殊的定位策略。

3. **自动化测试的维护成本**：前端 UI 频繁变动时，测试脚本的 XPath/CSS 选择器也需要同步更新，建议使用稳定的 data-testid 属性。

### 11.3 小组合作体会

1. **分工明确**提高了测试效率，每人专注 3 个功能点可以深入理解业务逻辑。

2. **交叉评审**发现了一些个人忽略的边界场景，如空数据状态、超长输入等。

3. **测试前需要充分了解业务**：理解系统的角色权限、业务流程对设计有效的测试用例至关重要。
