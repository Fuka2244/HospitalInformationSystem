## 1. 项目概览

本系统是一个医院信息系统（Hospital Information System），涵盖患者管理、预约挂号、药品查询、费用管理、医疗报告生成等核心功能，并集成AI能力（基于 LangChain4j + 通义千问）实现智能导诊、药物推荐、费用解释和报告自动生成。

### 功能模块总览

| 模块 | 说明 | AI增强 |
|------|------|--------|
| 患者账户管理 | 注册/登录/登出/修改信息/忘记密码 | 否 |
| 患者信息管理 | 患者基本信息/电子病历/就诊记录查询 | 否 |
| 预约系统 | 在线预约/取消/改期/排班查询 | 是：症状→科室+医生推荐 |
| 药品信息查询 | 药品列表/详情查询 | 是：症状→药品推荐(RAG) |
| 医疗费用查询 | 费用列表/详情/筛选 | 是：费用构成自然语言解释 |
| 医疗报告生成 | AI生成报告/PDF导出/确认 | 是：CoT思维链报告生成 |
| 科室信息 | 科室列表/详情/科室下医生 | 否 |

### 3.2 部署步骤

#### 步骤一：创建数据库

```sql
CREATE DATABASE IF NOT EXISTS his DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE his;
```

然后执行建表脚本 `src/main/resources/sql/his_schema.sql`。

#### 步骤二：修改配置

编辑 `src/main/resources/application.yaml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/his?serverTimezone=Asia/Shanghai&useUnicode=true&characterEncoding=utf-8&useSSL=false&allowPublicKeyRetrieval=true
    username: root          # ← 改为你的MySQL用户名
    password: your_password # ← 改为你的MySQL密码
  data:
    redis:
      host: localhost       # ← 改为你的Redis地址
      port: 6379

# AI配置 - 必须修改
ai:
  qwen:
    api-key: sk-xxxxxxxx   # ← 替换为你的通义千问API Key
    model-name: qwen-plus  # 可选: qwen-turbo, qwen-plus, qwen-max
    base-url: https://dashscope.aliyuncs.com/compatible-mode/v1
```

#### 步骤三：安装依赖并启动

```bash
mvn clean install
mvn spring-boot:run
```

服务启动后访问：`http://localhost:8080/HIS`

## 4. 数据库设计

### 4.1 ER关系图

```
patient(1) ──── (N)medical_record ──── (1)prescription ──── (N)prescription_item ──── (1)medicine
    │                    │
    │                    └──── (N)billing
    │
    ├──── (N)appointment ──── department
    │                  └──── doctor ──── department
    │
    └──── (N)medical_report

doctor ──── (N)doctor_schedule
department ──── (N)doctor
```

### 4.2 表结构详情

共 13 张表，完整 DDL 位于 `src/main/resources/sql/his_schema.sql`。

| 表名 | 主键 | 说明 | 关键索引 |
|------|------|------|---------|
| `patient` | account(VARCHAR36) | 患者信息 | uk_phone, uk_id_card |
| `department` | id(BIGINT AUTO) | 科室 | uk_name |
| `doctor` | id(BIGINT AUTO) | 医生 | idx_department_id |
| `admin` | id(BIGINT AUTO) | 管理员 | uk_username |
| `pharmacist` | id(BIGINT AUTO) | 药师 | - |
| `medical_record` | id(BIGINT AUTO) | 电子病历 | idx_patient_id, idx_doctor_id, idx_visit_date |
| `prescription` | id(BIGINT AUTO) | 处方 | idx_medical_record_id, idx_patient_id |
| `prescription_item` | id(BIGINT AUTO) | 处方明细 | idx_prescription_id |
| `medicine` | id(BIGINT AUTO) | 药品 | idx_name, idx_category |
| `appointment` | id(BIGINT AUTO) | 预约 | idx_patient_id, idx_doctor_id, idx_appointment_date |
| `billing` | id(BIGINT AUTO) | 费用 | idx_patient_id, idx_item_type, idx_create_time |
| `medical_report` | id(BIGINT AUTO) | 医疗报告 | idx_patient_id, idx_medical_record_id |
| `doctor_schedule` | id(BIGINT AUTO) | 医生排班 | uk_doctor_date_slot, idx_schedule_date |

### 4.3 状态码定义

**appointment.status**：0=已预约, 1=已完成, 2=已取消

**billing.status**：0=未支付, 1=已支付, 2=已退款

**billing.item_type**：REGISTRATION=挂号, EXAMINATION=检查, MEDICINE=药品, OTHER=其他

**prescription.status**：0=待取药, 1=已取药, 2=已取消

**medical_report.status**：0=草稿, 1=已确认, 2=已作废

**appointment.appointment_type**：DOCTOR=医生预约, EXAMINATION=检查预约

**medical_report.report_type**：EXAMINATION=检查报告, TREATMENT=治疗报告

## 5. 统一响应格式

所有接口返回统一的 JSON 格式：

```json
{
    "success": true,
    "errorMsg": null,
    "data": {},       // 或 [] 或 null
    "total": null     // 分页时返回总数
}
```

**成功（无数据）：** `{"success": true, "errorMsg": null, "data": null, "total": null}`

**成功（单对象）：** `{"success": true, "errorMsg": null, "data": {...}, "total": null}`

**成功（分页列表）：** `{"success": true, "errorMsg": null, "data": [...], "total": 100}`

**失败：** `{"success": false, "errorMsg": "错误原因", "data": null, "total": null}`

## 6. 认证机制

### 6.1 Session认证

系统基于 HttpSession 实现认证。登录成功后，Session 中存储：

| Key | 值 | 类型 |
|-----|------|------|
| `phone` | 用户手机号 | String |
| `account` | 用户UUID账户ID | String |
| `patient` | PatientInfoVo对象 | PatientInfoVo |

### 6.2 拦截器规则

`LoginInterceptor` 拦截 `/**` 路径，以下路径免登录：

| 免登录路径 | 说明 |
|-----------|------|
| `/patient/login/**` | 登录、忘记密码 |
| `/patient/register` | 注册 |
| `/medicine/list` | 药品列表 |
| `/medicine/*` | 药品详情 |
| `/medicine/ai-recommend` | AI药品推荐 |
| `/appointment/schedules` | 排班查询 |
| `/appointment/ai-recommend` | AI预约推荐 |
| `/department/**` | 科室信息 |
| `/error` | 错误页面 |
| `/static/**` | 静态资源 |

### 6.3 401响应

未登录访问受保护接口时返回 HTTP 401：

```json
{"success": false, "errorMsg": "请先登录", "data": null, "total": null}
```

## 7. 模块一：患者账户管理（含用户认证）

### 7.1 接口列表

| 方法 | URL | 说明 | 认证 |
|------|-----|------|------|
| POST | `/patient/register` | 用户注册 | 否 |
| POST | `/patient/login` | 用户登录 | 否 |
| POST | `/patient/loginout` | 用户登出 | 是 |
| GET | `/patient/me` | 查看个人信息 | 是 |
| PUT | `/patient/me/update` | 修改个人信息 | 是 |
| PUT | `/patient/login/forget` | 忘记密码 | 否 |

### 7.2 接口详情

#### POST /patient/register — 用户注册

**请求体：**
```json
{
    "name": "张三",
    "username": "zhangsan",
    "password": "123456",
    "confirmPassword": "123456",
    "gender": "男",
    "age": 25,
    "phone": "13800138000",
    "address": "北京市朝阳区",
    "idCard": "110101199001011234"
}
```

**响应：** 注册成功返回用户信息，account 由系统 UUID 生成

**Service实现说明（`PatientServiceImpl.register`）：**

1. 校验手机号格式（`RegexTool.isPhone`：1[3456789]开头的11位）
2. 校验身份证格式（`RegexTool.isIdCard`：15位或18位）
3. 查询手机号和身份证是否已被注册（`lambdaQuery` + `eq` + `or`）
4. 校验两次密码是否一致
5. UUID生成 account
6. BCrypt加密密码（`EncodePassword.encrypt`）
7. 保存到 patient 表（已合并User和Patient）

#### POST /patient/login — 用户登录

**请求体：**
```json
{
    "phone": "13800138000",
    "password": "123456"
}
```

**响应：**
```json
{
    "success": true,
    "data": {
        "username": "zhangsan",
        "account": "a1b2c3d4-e5f6-...",
        "gender": "男",
        "age": 25,
        "phone": "13800138000"
    }
}
```

**Service实现说明（`PatientServiceImpl.login`）：**

1. 校验手机号格式
2. 按手机号查询用户（`lambdaQuery.eq(Patient::getPhone, phone).one()`）
3. BCrypt校验密码（`MatchPassword.match`）
4. 构建 PatientInfoVo 存入 Session（key: `patient`, `phone`, `account`）

#### POST /patient/loginout — 用户登出

**Service实现：** `session.removeAttribute("patient")` + `session.invalidate()`

#### GET /patient/me — 查看个人信息

**响应：** 返回 Session 中的 PatientInfoVo

#### PUT /patient/me/update — 修改个人信息

**请求体：**
```json
{
    "username": "新用户名",
    "phone": "13900139000",
    "address": "新地址",
    "password": "当前密码"
}
```

**Service实现说明（`PatientServiceImpl.update`）：**

1. 从 Session 获取当前手机号
2. 验证当前密码
3. 如修改手机号：校验格式 + 查重
4. 条件更新非空字段（`lambdaUpdate.set(..., condition, ...)`）
5. 同步更新 Session 中的 phone 和 patientInfoVo

#### PUT /patient/login/forget — 忘记密码

**请求体：**
```json
{
    "phone": "13800138000",
    "newPassword": "654321",
    "confirmPassword": "654321"
}
```

**Service实现说明（`PatientServiceImpl.updatePassword`）：**

1. 校验手机号格式
2. 校验两次密码一致
3. 按手机号查找用户
4. BCrypt加密新密码并更新

### 8.1 接口列表

| GET | `/patient/{patientId}` | 指定患者信息 | 是 |

| GET | `/patient/medical-records?page=1&size=10` | 当前患者病历 | 是 |
| GET | `/patient/{patientId}/medical-records?page=1&size=10` | 指定患者病历 | 是 |
| GET | `/patient/medical-record/{recordId}` | 病历详情(含处方) | 是 |
| GET | `/patient/visit-history?departmentId=&doctorId=&startDate=&endDate=&page=1&size=10` | 历史就诊记录 | 是 |

### 8.2 接口详情

#### GET /patient/info — 当前患者基本信息

**响应：**
```json
{
    "success": true,
    "data": {
        "account": "uuid-xxx",
        "username": "zhangsan",
        "name": "张三",
        "gender": "男",
        "age": 25,
        "phone": "13800138000",
        "address": "北京市朝阳区",
        "idCard": "110101199001011234",
        "totalVisits": 5,
        "lastVisitDate": "2024-03-15T09:30:00"
    }
}
```

**Service实现说明（`PatientServiceImpl.getPatientInfo`）：**

1. 根据 patientId 查询 patient 表
2. 构建 PatientInfoVo（基础信息 + 统计就诊次数 + 最近就诊时间）
3. 就诊次数：`medicalRecordMapper.selectCount(eq("patient_id", patientId))`
4. 最近就诊：`selectOne(eq("patient_id", patientId), orderByDesc("visit_date"), LIMIT 1)`

| 输入 | 病历数据 + 检查结果 + 历史记录上下文 |

| 输出 | `ReportGenerationResult{summary, diagnosis, treatment, recommendation}` |
| RAG实现 | `buildHistoryContext()` 查询最近5条病历作为历史上下文 |
| 容错 | 解析失败返回占位文本 |

### 14.5 JSON解析策略

所有AI服务的 `parseXxx()` 方法统一处理三种响应格式：

1. **纯JSON**：直接解析
2. **```json代码块**：提取 ` ```json ` 和 ` ``` ` 之间的内容
3. **```代码块**：提取 ` ``` ` 之间的内容

解析失败时均返回兜底默认值（非null），保证接口不会因AI异常而崩溃。

### 14.6 RAG升级路线

当前版本使用"数据库全量查询 → Prompt注入"作为RAG的简化实现。后续可升级为：

```
当前：MySQL全量查询 → 构建文本 → 注入Prompt → LLM
升级：Embedding API → 向量数据库(Milvus/Qdrant) → Top-K检索 → 注入Prompt → LLM
```

升级步骤：
1. 将药品说明书/医学知识文档通过通义千问 Embedding API 生成向量
2. 存入 Milvus/Qdrant 向量数据库
3. 用户查询时先向量检索 Top-K 相关文档
4. 将检索结果注入 Prompt 替代当前的数据库全量查询
